# GliaKit starter — agent guide

You are working in a strict design system. Compose, don't invent — every
visual decision is already made in tokens and components.

## Stack

Next.js (App Router) · TypeScript · Tailwind v4 (CSS-first, no config file) ·
shadcn-style components · Prisma 6 (SQLite by default) · Clerk · Stripe ·
Resend. All services are optional-keyed: the app runs fully on demo data
(`src/lib/data.ts`) with an empty `.env`.

## Design system (non-negotiable)

- **Colors**: semantic Tailwind tokens only — `bg-background`, `bg-card`,
  `bg-muted`, `text-foreground`, `text-muted-foreground`, `border-border`,
  `text-primary` (accents), `text-primary-ink` (brand-coloured text and
  icons, kept at 4.5:1), `bg-primary-strong` for solid violet fills
  under white text (AA contrast; plain `bg-primary` fails with white),
  `text-destructive`, `warning`/`warning-foreground`,
  `diff-add` (success). NEVER hardcode hex in components. Inline notices
  use the `Alert` component.
- **Signature gradient** `var(--gradient-signal)` is reserved for: one hero
  keyword, the gradient Button variant, signal dividers / one chart
  highlight. Nothing else.
- **Type**: headings = `font-heading font-semibold tracking-tight`
  (Bricolage Grotesque); body = default sans (Geist); eyebrows/labels/
  numbers = `font-mono` (JetBrains Mono). Eyebrow recipe:
  `font-mono text-eyebrow uppercase tracking-[0.15em] text-muted-foreground`.
- **Structure**: hairline borders (`border-border`), not shadows.
  Buttons and form controls `rounded-md` (8px); badges and chips
  `rounded-full`. Cards and other surfaces (dialogs, lists, table
  wrappers) `rounded-lg border bg-card` (12px, as in Figma).
- Light theme is Talvo's default; using semantic tokens keeps both themes correct.
  Switching is wired via next-themes (`src/components/theme-provider.tsx`)
  with a `ThemeToggle` in the sidebar footer and landing header — never
  hardcode a `dark` class on elements.

## Words

Every label, empty state, error, toast and email follows `VOICE.md`:
sentence case, buttons that name the act ("Save changes", never "Submit"),
errors that say what happened and how to fix it.

## Where things live

- UI primitives: `src/components/ui/*`, about 45 components covering
  actions, forms (incl. OTPInput, Combobox, DateRangePicker, FileUpload),
  data display (Card, Table with sortable TH, TableToolbar, the
  dependency-free charts), feedback, navigation and overlays (Dialog,
  Sheet, Drawer, Popover, CommandPalette). Full list in
  `.cursor/rules/design-system.mdc`; docs with live previews at
  https://www.gliakit.com/components.
- Studio output: `src/components/studio/blocks.tsx` (every section as one
  typed component, built only from `src/components/ui`) and
  `src/components/studio/frames.tsx` (the app shell: layout, composable
  sidebar, top bar, page frames, tabs, overlays). Generated by GliaKit
  Studio; copy-owned, edit freely.
- The demo app, Talvo (a brewery's cash in view): its shell is
  `src/components/app/talvo.tsx` (`TalvoFrame`: the pages, their routes and
  the sidebar's blocks), its screens are `src/app/(app)/*`, each a
  `TalvoFrame` with sections laid out in `Columns` and `Stack`s and every
  bit of content passed in as props right there. ⌘K lives in
  `src/components/app/command-palette.tsx`.
- Design source: `design/talvo.studio.json` is the Studio plan and theme the
  screens were exported from (every page's sections and props); regenerate
  from it with GliaKit Studio's export rather than editing blocks by hand.
- Theme: the block at the end of `src/app/globals.css` (brand colour,
  radius, density, fonts) and the `data-*` attributes on `<html>` in
  `src/app/layout.tsx` (card effects; button, input, badge, table, tabs
  and avatar styles; `data-controls` for one shared control height;
  `data-field` for where labels sit). Change values there; every
  component follows. Buttons, inputs, selects and pickers all take the
  `h-control` height, so they line up in any form or toolbar; label a
  control with the kit's `Field` (with `htmlFor`) so label placement
  follows the theme.
- Auth screens: `src/app/(auth)/*`. Demo data for the kit's older
  components: `src/lib/data.ts` · DB: `prisma/schema.prisma` +
  `src/lib/db.ts` · Service flags: `src/lib/env.ts`
  (`features.auth/db/payments/email`) · Reusable prompts: `prompts/` ·
  Cursor rules: `.cursor/rules/`.

## Adding a screen

1. `src/app/(app)/<route>/page.tsx` — wrap it in `TalvoFrame` with the
   page's nav index, start with `PageHeaderBlock`, then blocks in
   `Columns`.
2. Register it in `NAV` and `LINKS` in `src/components/app/talvo.tsx`
   (and the ⌘K palette), and in the protected routes of
   `src/proxy.ts`.
3. Content is the blocks' props; wire real data in the page file.
4. Export `metadata` with a title. Follow `/payments` for list screens
   (filter bar + data table), `/settings` for tabbed screens (`OnTab`),
   `/calendar` for a week grid.

## Verify

`npx tsc --noEmit` must pass. `npm run build` before claiming done.
