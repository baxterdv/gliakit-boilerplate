# GliaKit — starter

A Next.js SaaS starter with a **real design system**: the same tokens in
Figma, code, and your AI tools. Thirteen screens, with route protection,
payments, database and email ready to switch on — composable, on-brand, and
readable by Cursor and Claude Code.

## Quickstart (zero config)

```bash
npm install
npm run dev
```

Open http://localhost:3000 — the landing page, `/dashboard`, and all
thirteen screens run on demo data with **no keys required**.

## The 13 screens

Landing · Pricing · Sign in · Sign up · Reset password · Dashboard ·
Cash flow · Payments · Calendar · Deals · Reports ·
Settings (tabbed) · 404

The app screens are the Talvo demo (a brewery's finances), generated by
GliaKit Studio from the same blocks you build with. `/emails` previews the
transactional emails in development.

## Switch on the integrations

Copy `.env.example` to `.env` and add keys — each one activates its
integration on restart (see `src/lib/env.ts`):

| Integration | Keys | What switches on |
|---|---|---|
| **Database** (Prisma · SQLite) | `DATABASE_URL` | `npm run db:push && npm run db:seed`, then swap screens to DB reads |
| **Auth** (Clerk) | `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY` | `src/proxy.ts` protects the app routes, with Clerk's own sign-in. The sign-in, sign-up and reset screens are designs, ready to connect to Clerk's components |
| **Payments** (Stripe) | `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | `/api/checkout` + `/api/webhooks/stripe` |
| **Email** (Resend) | `RESEND_API_KEY`, `EMAIL_FROM` | `sendWelcomeEmail()` in `src/lib/email.ts` |

## Build with AI

This starter ships with rules your AI tools read automatically:

- `.cursor/rules/design-system.mdc` — tokens, typography, component law
- `.cursor/rules/screens.mdc` — how screens are composed
- `CLAUDE.md` / `AGENTS.md` — the same system for Claude Code
- `prompts/` — fill-in-the-brackets prompts for new screens and CRUD tables

Try it: paste `prompts/new-screen.md` into Cursor with your own screen
idea. The result lands on-system — same tokens, same components.

## The system in one paragraph

Semantic tokens only (`bg-background`, `bg-card`, `text-foreground`,
`text-muted-foreground`, `border-border`, `bg-primary`) — never hex.
Headings are Bricolage Grotesque (`font-heading`), body is Geist, labels
and numbers are JetBrains Mono. Hairline borders do structure; the
violet→cyan signature gradient is reserved for the hero keyword, the
gradient button, and signal dividers. Dark is default; semantic tokens
make light mode free.
